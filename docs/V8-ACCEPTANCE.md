# Приёмка v8 и известные ограничения

## Проверено 20 октября 2026 (локально, macOS, Node 24.19.0)

- TypeScript `--noEmit` без ошибок; **50 из 50 тестов** (43 теста v7 + 7 тестов радара).
- Склейка историй на TypeScript совпадает с прототипом на Python на одних и тех же 409 статьях: те же главные истории и число изданий.
- Миграции `0000`–`0007` применяются к локальной D1.
- Радар в Worker (miniflare): 14 лент, 519 статей, без ошибок; проверенные истории в интерфейсе.
- «Сделать выпуск»: один запрос DeepSeek (`deepseek-flash`, 7 с) → 4 выпуска RU/UZ/KK/EN в «Мои выпуски» и 4 задания монтажа.
- Runner: 4 ролика 1080×1920 с озвучкой, фото Pixabay, субтитрами и источниками; ≈ 15–45 с на ролик.
- Отказоустойчивость: загрузка не удалась → аренда истекла → runner сам смонтировал и загрузил повторно; перезапуск студии runner пережил без падения.
- Публикация из студии: Telegram (личный чат с ботом) и YouTube Shorts (канал владельца) — обе успешны.
- Исправление загрузки > 1 MB: MP4 8,5 MB через `/api/media` — 413 до, 200 после.
- Интерфейс радара проверен скриншотом (desktop 1440 px), ошибок в консоли нет.
- Docker-образ runner (`python:3.13-slim`, 604 MB) собирается; внутри контейнера с `read_only`, `cap_drop: ALL`, `tmpfs /tmp` прошёл полный монтаж с озвучкой; шрифт DejaVu Sans Bold рисует кириллицу и казахские буквы.

## Не проверено

- Деплой в Sites и работа на опубликованном сайте (нужен аккаунт владельца). В частности: исходящие запросы Worker к RSS-лентам, `HTMLRewriter`, лимиты CPU на склейку ~500 статей, применение миграции `0007`.
- Публикация в Telegram-**канал** (проверен личный чат; путь канала отличается только проверкой прав бота).
- Длительная работа автопилота по расписанию (проверены ручной запуск и шаг `tick`).
- Мобильная вёрстка радара на реальном телефоне (стили есть, скриншот не делался).
- Работа контейнера runner против опубликованного сайта (локально runner запускался без Docker).

## Сценарий приёмки на сайте

1. Развернуть v8 и runner (`V8-DEPLOY.md`). Статус «Runner активен».
2. Подключить DeepSeek. В радаре — «Обновить ленты»: есть истории с 2+ изданиями и ссылками.
3. Согласие → «Сделать выпуск» на одной истории. Через 1–2 мин: ролики на выбранных языках, выпуски в «Мои выпуски».
4. Посмотреть ролики: озвучка, субтитры, источники, отсутствие выдуманных фактов (сверить со ссылками).
5. Подключить Telegram-канал и YouTube; опубликовать ролик; проверить ссылки и подписи.
6. Включить автопилот «Проверка редактором», интервал 15 мин, лимит 2. Через 15–30 мин — новая история без участия человека.
7. Переключить «Публиковать сразу» и убедиться, что ролики уходят на площадки сами, а лимит в сутки соблюдается.
8. Открыть выпуск радара в студии и при желании пересобрать с AI-ведущим (премиум-путь v7).

## Ограничения

- **Edge-TTS** — бесплатный неофициальный интерфейс голосов Microsoft Edge; может измениться или ограничить доступ. Запасной путь — ElevenLabs/HeyGen из v7. Runner повторяет озвучку, если голос оборвался (< 90 % слов).
- **YouTube**: непроверенное приложение Google — загрузки могут быть приватными, доступ истекает через 7 дней в режиме Testing, квота ограничивает число загрузок в сутки.
- **Факты**: модель пересказывает только анонсы и текст одной статьи; фильтр рисков пропускает темы насилия над детьми, сексуальных преступлений и суицида. Редакторская проверка рекомендуется — по умолчанию включён режим «Проверка редактором».
- **Картинки** — стоковые фото Pixabay по смыслу истории, не фото самого события. Чужие фото из статей не используются (авторское право).
- **Источники** — англоязычные мировые издания; сценарии переводятся моделью. Узбекский и казахский текст стоит проверить носителю языка.
- **Дайджест «5 главных новостей дня»** из прототипа в v8 пока не перенесён.
- Telegram Bot API принимает видео до 50 MB (ролики радара 5–18 MB).
