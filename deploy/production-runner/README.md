# Runner производства (v8)

Постоянный фоновый сервис студии. Каждые 15 секунд:

1. `POST /api/internal/production` — продвигает очередь HeyGen/Shotstack (функция runner v7 без изменений);
2. `POST /api/internal/autopilot {"action":"tick"}` — новостной радар и автопилот; частоту сбора лент и создания историй ограничивает сервер;
3. забирает задания монтажа (`claim`), делает ролик 1080×1920 и загружает MP4 обратно (`multipart`: `id`, `token`, `file`); при ошибке сообщает `fail`.

Монтаж: озвучка Edge-TTS (RU/UZ/KK/EN) с таймингом слов → фото Pixabay с плавным зумом → плашка бренда, заголовок, субтитры с подсветкой слова и строка источников (Pillow) → FFmpeg H.264/AAC.

В Sites не подтверждена поддержка постоянного Cron/Queue worker, поэтому runner — отдельный сервис. Без него ролики радара не монтируются и автопилот не запускается; ручной процесс v7 продолжает работать, пока открыта страница «Сцены и монтаж».

## Запуск

```bash
umask 077
cat > .env <<EOF
STUDIO_URL=https://<домен-студии>
PRODUCTION_RUNNER_TOKEN=<тот же секрет, что в Sites>
PIXABAY_API_KEY=<ключ Pixabay, необязательно>
EOF
chmod 600 .env
docker compose up -d --build
docker compose logs --tail=30 production-runner
```

Проверка: «Новостной радар» и «Сцены и монтаж» показывают «Runner активен».

## Безопасность и надёжность

- Доступ к студии — только Bearer `PRODUCTION_RUNNER_TOKEN`; ключи DeepSeek, Telegram, YouTube, HeyGen runner не получает. Не публикуйте `.env` и логи.
- Задание монтажа выдаётся с арендой на 10 минут. Если загрузка не подтвердилась, аренда истекает и задание возвращается в очередь — повторный монтаж бесплатный.
- Ошибка монтажа отмечается в студии, автоматического повтора нет.
- Контейнер: `read_only`, `cap_drop: ALL`, `no-new-privileges`, пользователь `nobody`, `tmpfs /tmp`.
- Остановка: `docker compose stop production-runner`. Перед откатом версии сайта остановите runner.

Runner не использует app-коннекторы пользователя (BulkPublish). Публикация в Telegram и YouTube выполняется сервером студии с ключами владельца.
