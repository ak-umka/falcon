# Runner производства

В Sites не подтверждена поддержка постоянного Cron/Queue worker для этого проекта. Поэтому интерфейс показывает фактический heartbeat внешнего runner. Без него обработка продолжается только пока открыта страница «Сцены и монтаж». Задания и снимки выпуска сохраняются в D1 в обоих режимах.

Разверните эту папку на постоянно работающем сервере с Docker Compose:

1. Создайте случайный секрет: `openssl rand -hex 32`.
2. Сохраните его как secret `PRODUCTION_RUNNER_TOKEN` в runtime окружении Sites и повторно разверните сохранённую версию сайта. Не меняйте `PROVIDER_ENCRYPTION_KEY`.
3. Создайте локальный `.env` с правами 600: `STUDIO_URL=https://falcon-news-studio.zafar-safaro-0684.chatgpt.site` и `PRODUCTION_RUNNER_TOKEN` с тем же значением. Не добавляйте `.env` в Git.
4. Выполните `docker compose up -d --build` в этой папке.
5. Откройте страницу «Сцены и монтаж»: статус «Runner активен» должен появиться после первого успешного запроса. Проверьте реальный выпуск при закрытом браузере и сохранение результата после повторного входа.

Runner обрабатывает один выпуск за тик, с серверной арендой на 5 минут. Повторный тик использует те же request keys. Неопределённый ответ провайдера блокирует выпуск; автоматического повторного платного запроса нет. Пауза запрещает следующие этапы, но уже отправленный запрос у провайдера не отменяет.

Runner не публикует в соцсети и не использует пользовательские app-коннекторы. Публикация остаётся отдельным действием после просмотра.

Файлы для монтажа передаются по подписанным ссылкам сроком 6 часов, без API-ключей. Ссылки не выводятся в интерфейс; не публикуйте их в логах. При изменении домена задайте серверную переменную SITE_PUBLIC_URL. Если сайт станет owner-private, внешнему renderer потребуется отдельно поддержанный механизм доступа — не меняйте аудиторию автоматически.
